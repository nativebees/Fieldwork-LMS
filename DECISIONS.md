# Decision log

Decisions actually made while building Fieldwork v0.1, with the reason for each. Dated 2026-11-25.

| #   | Decision                                                                                                           | Why                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Hash navigation (`#/studio`) instead of path routing                                                               | Direct links survive a reload on any static host with no rewrite rule.                                                             |
| 2   | One reducer holds the program, and the studio, preview, review and exports all read it                             | A single source of truth is what makes "editing updates the preview" true by construction.                                         |
| 3   | The reducer is pure. Time is passed in and ids come from a counter in state                                        | State transitions are testable without mocks.                                                                                      |
| 4   | Tailoring and constraint suggestions produce a whole next program that is previewed, then applied or cancelled     | The preview and the "what changed" views can use the same diff. Nothing reaches the program without consent.                       |
| 5   | Suggestion status is derived from the program, not stored                                                          | A manual drag-and-drop swap counts as applied, and feedback can cite actual program state.                                         |
| 6   | The assessed requirements are the Practice and Evidence fields. Content blocks are not assessed                    | It gives "freeform edits to assessed requirements" a precise meaning. Editing either field marks the lesson custom until reviewed. |
| 7   | A material objective change means fewer than 80% of distinct words are shared with the aligned version             | A transparent rule is better than pretending to judge meaning.                                                                     |
| 8   | Typed exercises are built from three part types (order, pick one, pick many) and declarative criterion rules       | Six assessment templates and two upgraded versions share one scoring function, with explicit criterion ids.                        |
| 9   | The workflow and transfer lessons have a version 2 assessment that adds the claim check and owner approval         | It makes the assessment revision inspectable and shows earlier attempts being kept against version 1.                              |
| 10  | Two of the five seller criteria read the program itself                                                            | Good conversation choices alone score 7 of 10. The plan has to change for the rest.                                                |
| 11  | The initial recommendation locks when the sponsor shares the constraint                                            | The before and after comparison stays honest.                                                                                      |
| 12  | The second module's header is an item in one flat sortable list                                                    | Cross-module dragging and keyboard sorting work with one sortable context.                                                         |
| 13  | Templates are inserted before the item they are dropped on. Lessons take the place of the item they are dropped on | It matches what the insertion line and the sortable animation show.                                                                |
| 14  | Coaching and analytics providers are asynchronous even though the scenario versions resolve immediately            | The interface is already shaped for a real call, with loading and error states.                                                    |
| 15  | The live coaching provider exists only as an unavailable placeholder, with a response validator                    | The boundary is visible and tested, and nothing can appear under a live label by accident.                                         |
| 16  | The cohort view is a table with a thin segmented bar per row                                                       | The reader needs the figures. The bar shows the split, and unavailable values get a hatch.                                         |
| 17  | The chart uses blue between terracotta and green                                                                   | The palette validator showed terracotta and sage collapse under protanopia.                                                        |
| 18  | Newsreader, Instrument Sans and IBM Plex Mono are bundled, Latin subset only                                       | No runtime font CDN. The italic uses the weight-only file, which saves about 82 kB.                                                |
| 19  | Tailwind v4 with tokens defined in CSS, and a test that reads that CSS to check contrast                           | One place defines the colours and one test guards them.                                                                            |
| 20  | Saved state that fails validation is discarded, not migrated                                                       | A prototype with one schema version does not need migrations. The visitor is told when this happens.                               |
| 21  | The "ten-minute version" keeps every assessed practice, removes worked examples and trims explanations             | Shortening should not quietly drop what is scored.                                                                                 |
| 22  | "Active" in the fixture means at least one chat day                                                                | It keeps the fixture small. The difference from the documented definition is recorded in `EVIDENCE.md`.                            |
| 23  | The role posting is marked "needs review" with no summary                                                          | Its host was unreachable during the build, and an unread page should not be summarized.                                            |
| 24  | `@playwright/test` is pinned to 1.63.0                                                                             | It matches the browser preinstalled in the build environment. It can be raised freely.                                             |
| 25  | Nothing was published and no Artifact was created                                                                  | The brief asks for approval before any publication.                                                                                |
